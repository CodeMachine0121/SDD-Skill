sdd-skills · Claude Code Plugin

從領域語言到正式程式碼的開發工作流

8 個 skill 各自負責一個階段,職責分明、交接乾淨。所有 skill 共用 .sdd/ 資料夾作為工作區,形成領域知識、需求與決策的活紀錄。

各 Stage 卡片

每張卡片說明用途,以及使用者的 Input 與產出的 Output。

1 ubiquitous-language-mapping

/ul-init · /ul-update

地基。掃描既有程式碼,建立領域術語表,對齊「業務用語 ↔ 程式命名 ↔ UI 文字」。下游所有 skill 都靠它用專案自己的語言提問與產出。

Input 既有 codebase(INIT);語言演進的增修需求(UPDATE)
Output .sdd/UL-MAP.md

2 clarify

/clarify

寫程式前先達成「意圖共識」,再用具體範例(happy path + 邊界 + 例外)把行為釘死。純業務語言,只講 what 不講 how。

Input 一句功能需求,並在共識迴圈中回答提問、確認範例
Output .sdd/{date}-{feature}/BRIEF.md

3 prd

/prd · /prd project

以 UL Map 為基礎做需求訪談,產出正式 PRD,並把範例轉成 inline 的 Gherkin 驗收條件。Project 模式則產出/更新專案總覽。

Input 回答需求訪談(Feature);或直接同步架構(Project)
Output PRD.md 或 .sdd/PROJECT.md

4 architecture

/architecture · /arch

PRD 刻意略過的「how」階段。設計變更範圍、新模組職責(表格),以及讓未來需求便宜可加的接縫(seam),並把每個 scenario 對應到負責元件。

Input 已完成的 PRD.md(自動讀取 PROJECT/UL-MAP 與 codebase)
Output .sdd/{date}-{feature}/ARCH.md

5 tdd

/tdd

依 PRD.md + ARCH.md 做 red-green-refactor 實作。每個 cycle 都 commit,進度存 SQL 可續作。

Input 審核 skill 提出的 test plan 並確認
Output 實作程式碼 + 測試(綠燈套件)+ 逐 cycle commit

＋ contract

/contract

以驗收準則(AC)為 oracle 驗證實作是否符合契約(PRD 優先,否則 BRIEF)。每條 clause 先從規格推導應有結果,再獨立判斷測試有無斷言它、程式碼有無產出它。標出 violations / mis-asserted / gaps / partial / orphans。屬靜態稽核,不跑完整套件,不改 source。

Input 已有實作 + .sdd/{feature}/ 契約文件
Output .sdd/{feature}/CONTRACT.md(Traceability Matrix)

＋ visionize

/visionize

把 BRIEF/PRD 變成一頁自包含 HTML,讓團隊「看見」計畫(目標、範圍、人物誌、流程圖、Gherkin 情境、風險)。只投影不創作,缺漏標 TBD。

Input .sdd/{date}-{feature}/ 內的 BRIEF 和/或 PRD
Output .sdd/{date}-{feature}/VISION.html

＋ improve-codebase

/improve-codebase

找出散落邏輯,收斂成 deep module(穩定介面吸收複雜度,呼叫端保持簡單),並補介面測試。與功能無關,隨時可跑。

Input 指定要改善的既有 codebase
Output 重構後的模組 + 介面測試

使用建議

新專案起手

/ul-init → /prd project
先建立領域地基與專案總覽。

開發新功能

/clarify → /prd →(可選 /visionize)→ /architecture → /tdd

持續維護(不綁功能)

/prd project、/improve-codebase、/ul-update、/contract 隨時可跑。

共享工作區 .sdd/ 結構:UL-MAP.md · PROJECT.md · {yyyy-MM-dd}-{feature}/(BRIEF.md · PRD.md · ARCH.md · VISION.html · CONTRACT.md)
